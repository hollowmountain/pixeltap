# PixelTap — сайт-визитка

Статический сайт. Ни сборки, ни зависимостей: три файла и каталог в JSON.

```
index.html      разметка
css/site.css    визуальный мир
js/site.js      сетка курса, переключение утро/вечер, каталог
products.json   товары — единственный файл, который вы правите регулярно
```

## Запуск локально

```bash
python -m http.server 8420
```

Затем откройте `http://localhost:8420`. Просто открыть `index.html`
двойным щелчком нельзя: браузер заблокирует чтение `products.json`.

## Идея сайта

Уход работает курсом, а не разовой покупкой. Поэтому страница построена
как трекер ритуала, а не как витрина с баночками: сетка курса на 28 дней,
переключатель **Утро / Вечер**, который меняет и палитру, и состав шагов.

При первом заходе сайт сам открывается в текущем времени суток
посетителя (утро с 5:00 до 17:00), затем запоминает выбор.

## Как добавить или изменить товар

Весь каталог живёт в `products.json`. HTML трогать не нужно.

```json
{
  "step": "Сыворотка",
  "phase": "evening",
  "name": "Сыворотка с ретинолом",
  "volume": "30 мл",
  "desc": "Короткое описание в одно-два предложения.",
  "ozon": "https://www.ozon.ru/product/1234567890/",
  "wb": "https://www.wildberries.ru/catalog/12345678/detail.aspx",
  "img": ""
}
```

Правила:

- `phase` — одно из: `morning`, `evening`, `both`. Определяет, под каким
  фильтром товар показывается.
- `step` — шаг ритуала: «Очищение», «Тоник», «Сыворотка», «Крем», «SPF»
  и т. п. Выводится над названием.
- `ozon` и `wb` можно оставить пустыми (`""`) — кнопка станет неактивной
  вместо ссылки в никуда.
- Товары идут на сайте в том же порядке, что в файле.
- Не забывайте запятые между `{ }` — иначе каталог не загрузится.
  Проверить файл: jsonlint.com.

## ⚠️ Что обязательно заменить перед публикацией

Сайт собран до получения реального каталога. Ниже — всё, что сейчас
стоит временно.

### 1. Товары — демонстрационные

`products.json` содержит **восемь придуманных позиций** с флагом
`"placeholder": true`. Это не товары PixelTap, а заглушки, чтобы показать
раскладку. Пока хоть у одной позиции стоит этот флаг, на сайте видна
честная плашка «Каталог в наполнении».

**Заменить на реальный каталог и удалить флаг** — плашка исчезнет сама.

### 2. Ссылки на кабинеты — проверить

В `index.html` стоят:

- `https://www.ozon.ru/seller/pixeltap/`
- `https://www.wildberries.ru/seller/232922`

Вы давали ещё `ozon.ru/seller/pixeltapic` — уточните, какой кабинет
основной, и поправьте при необходимости.

### 3. Реквизиты — сверить

В разделе «О бренде» указаны данные, полученные из публичного справочника
продавцов Wildberries:

- ИП Арасланова З. Г.
- ОГРНИП 321745600074072
- ИНН 744402248532

**Сверьте с документами.** Если у марки другое юрлицо — исправьте.

### 4. Чего на сайте намеренно нет

Я не стал писать то, что нельзя подтвердить: собственное производство,
лабораторию, число клиентов, годы на рынке, сертификаты, рейтинги.
Если такие факты есть — пришлите, добавлю в раздел «О бренде».

### 5. Фотографии товаров

Сейчас их нет вовсе — раскладка держится на типографике. Когда появится
доступ к каталогу, фото подставляются в поле `img`; в вёрстке под них
уже есть место в строке товара.

## Автоматическая выгрузка каталога с Ozon и Wildberries

Вместо ручного заполнения `products.json` его можно собрать прямо из
кабинетов:

```bash
node tools/fetch-catalog.mjs --dry
```

`--dry` показывает результат, ничего не записывая. Без флага — пишет
`products.json`.

### Почему это скрипт, а не запрос с сайта

Ключ продавца — это доступ к кабинету: им можно менять цены, править
и удалять карточки, читать заказы. Всё, что попадает в JavaScript на
сайте, посетитель читает через инструменты разработчика за две секунды.
**Ключи не должны оказаться на сайте ни при каких условиях.**

Поэтому схема такая: скрипт запускается у вас на машине, ходит в API
с вашими ключами и кладёт рядом обычный статичный `products.json`. Сайт
остаётся статикой и никаких ключей не знает.

### Где взять ключи

**Wildberries** — личный кабинет продавца → Настройки → Доступ к API.
Нужна категория **«Контент»**. Ставьте права **только на чтение**: скрипт
ничего не меняет, а при утечке ключом нельзя будет испортить карточки.
Токен показывается один раз при создании.

**Ozon** — Seller API в кабинете продавца. Нужны два значения:
**Client-Id** и **Api-Key**. С сентября 2025 при создании ключа
указываются разрешённые категории доступа — дайте минимум на чтение
товаров.

### Как передать ключи скрипту

Ключи берутся из переменных окружения, в файлы их писать не надо.

PowerShell:

```powershell
$env:WB_TOKEN="ваш_токен"; $env:OZON_CLIENT_ID="ваш_id"; $env:OZON_API_KEY="ваш_ключ"; node tools/fetch-catalog.mjs --dry
```

Можно указать только одну площадку — вторая пропустится.

### Что скрипт делает

- **Wildberries**: `POST /content/v2/get/cards/list`, постранично по
  курсору, берёт название, артикул, фото, объём из характеристик.
- **Ozon**: `POST /v3/product/list` за идентификаторами, затем
  `POST /v3/product/info/list` за карточками пачками по 100.
- **Склеивает** товар, который есть на обеих площадках, в одну строку —
  по артикулу продавца (`vendorCode` у WB, `offer_id` у Ozon).
- **Раскладывает по ритуалу** — угадывает шаг и время по названию
  («сыворотка», «spf», «тоник»…). Это догадка, её нужно проверить.

### Ручные правки

Описания товаров API не отдаёт в пригодном для сайта виде, а угаданный
шаг иногда мимо. Правки пишутся в `tools/catalog-overrides.json` по
артикулу и **переживают следующую выгрузку** — скрипт накладывает их
поверх свежих данных:

```json
{
  "byArticle": {
    "PT-SER-30": { "desc": "Работает ночью.", "step": "Сыворотка", "phase": "evening" }
  },
  "order": ["PT-SER-30"]
}
```

`order` задаёт порядок товаров на сайте.

### Что проверено, а что нет

Скрипт написан по официальной документации. Адрес и авторизацию
Wildberries я проверил вживую — API ответил корректной ошибкой на
неверный токен, значит запрос уходит правильный. **До Ozon из моей
среды достучаться не удалось** (соединение рвётся на сетевом уровне),
поэтому его ветку проверьте у себя первым запуском с `--dry`.

Если увидите «Это проблема связи, а не ключей» — дело в сети, повторите.
При неверных ключах площадка отвечает понятной ошибкой с текстом.
